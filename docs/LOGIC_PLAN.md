# Логика и вывод: план (с 25.10.2026)

Решение владельца: логика ZX переносится через **JS-модель** (сверка с ZX по шагам), потом — **i8080 с
оптимизацией** (сверка с JS-моделью). Цвет — 3 плоскости без клэша. Вывод графики — **по максимуму
процедурами на SP** (данные спрайтов читаются `pop`, где можно — и запись `push`).

## Этапы
0. **Эталон ZX** — готов. `tools/zx48.js`: Z80 (tools/vendor/Z80.js из aticatac-v06c), ПЗУ 48K (ref/48.rom
   из SkoolKit), клавиатура по порту 0xFE, кадр 69888 тактов, INT 32 такта (при DI теряется, как на ZX),
   без спорной памяти. Игра — картриджная сборка из skool (build/jetpac.bin), старт 0x6000.
   `node tools/zx_trace.js research/scenarios/<имя>.json` → build/golden/<имя>.json.gz.
1. **JS-модель** (src/model/) — готова: проход главного цикла целиком, вывод в экран ZX (экран — часть
   состояния). `node tools/model_run.js build/golden/*.json.gz` — 8 эталонов, ~70 тыс. проходов, 0 расхождений.
2. **i8080** (src/vec/) — готов: `tools/build_vec.sh` -> build/vec/jetpac.bin, rom/jetpac.r0m, .c00.
   Сверка `node tools/lock80.js build/golden/<имя>.json.gz [--prof]`: i8080 выполняет `pass` от состояния
   эталона с теми же входами (чтения FRAMES — перехват 0x5C78 из очереди шага, ld a,r — r_buf, клавиши —
   zx_kb); сравниваются переменные 0x5CF0..0x5DFF, экран (объединение 4 плоскостей), звуки. Все 8 эталонов —
   0 расхождений. Сверка идёт прямо с эталоном ZX (модель с ним совпадает).
3. **Игра на Векторе** — первая живая версия (src/vec/main.asm): меню, игра, конец игры, палитра в ISR,
   клавиатура + стрелки/пробел + джойстик «П», мигание FLASH, звук на ВИ53. Снимки без окна:
   `node tools/vecshot.js rom/jetpac.r0m <кадров> "100:5+ 104:5- ..." out.png`.

## Шаг и состояние
- Шаг = проход главного цикла: `MainLoopResetStack` → объекты ракета (0x5D30), модуль (0x5D38), предмет
  (0x5D40), пламя (0x5D48), 6 пришельцев (0x5D50..), взрыв Джетмена (0x5D80) → `NewActor_4` →
  `MainLoopResetStack`. На каждой итерации объекта: если FRAMES ≠ last_frame — **вложенный проход**
  Джетмена (0x5D00), 4 лазеров (0x5D08..) и звука взрыва (0x5D28) до ракеты; его конец сделан
  самомодификацией `NewActor` (`ld bc,nn` → rocket_state, `ld a,(nn)` → `JP ResetModifiedInFrame`).
- Значит, **Джетмен и лазеры — 50 раз в секунду**, а ракета, предметы и пришельцы — раз за проход:
  их скорость зависит от быстродействия. На ZX в игре ~2 кадра на проход (s0_random: 2,08).
- Состояние в эталоне: 0x4000..0x7FB2 без системной области 0x5B00..0x5CEF (стек, переменные ПЗУ):
  экран, атрибуты, переменные, буферы спрайтов (0x5E00..), код (самомодификация `NewActor`).
- Входы модели из эталона: чтения FRAMES (очередь `rd`), порты (`in`, по порядку, с номером порта),
  `ld a,r` (`r`). Генератор случайных чисел читает ПЗУ: `add a,(hl)` с HL = 0x00..0xFF и после первого
  кадра `ld a,($0244)` (самомодификация оставляет адрес 0x0244 вместо random_number) — на Векторе нужна
  копия этих байт ПЗУ (257 байт: 0x0000..0x00FF и 0x0244).
- Звук: входы в PlaySquareWave1 / PlaySquareWav2 / SfxLaserFire / SfxPlayExplosion с регистрами
  (сверяются значимые: c, d; для Wav2 ещё b — первая полуволна берёт B от вызывающего кода).

## Тонкости, найденные по дороге
- **Лазер читает экран**: `LaserBeamAnimate` при Y < 128 останавливает луч на непустом байте экрана.
  Поэтому модель рисует в экран ZX буквально, и на Векторе проверка должна смотреть объединение плоскостей.
- Вывод `MaskSprite`: построчно (снизу вверх) стирает строку старого кадра (AND NOT) и рисует строку нового
  (OR) — на двух наборах регистров, `exx` между ними; первые строки — только стирание (или только рисование)
  на разницу высот. В модели — буквально с регистровым файлом (src/model/draw.js, `maskLoop`).
- `ColourizeSprite` начинается с `exx` и оставляет наборы переставленными; дальше код на это опирается.
- Чёрный предмет (химическое оружие мигает цветом 0): на ZX пиксели есть (лазер о них стопорится), в 3
  плоскостях их не будет. Расхождение редкое — решить на этапе 3 (возможно, 4-я плоскость как «наличие»).
- В эталоне шаг может начаться с подачи прерывания ровно на `MainLoopResetStack` — граница шага: PC на метке
  и уже выполнена хотя бы одна команда игры.
- Метка `PlaySquareWav2` — цель собственного `djnz`: вход в звук считается, только если прошлая команда
  была вне тела подпрограммы.

## Этап 3: вывод на Векторе (наброски)
- Экран Вектора: байт = 8 точек по горизонтали, столбец из 256 байт подряд (адрес + 1 = строка выше) —
  строка спрайта снизу вверх = `inr l`, столбец спрайта = подряд идущие байты: данные спрайтов хранить по
  столбцам и читать `pop`.
- Плоскости: 3 под цвет INK, 4-я свободна (палитра её игнорирует) — 8 КБ памяти под код/данные.
- ZX 256×192 → Вектор 256×256: игровое поле по центру по вертикали (32 строки сверху и снизу).
- Без клэша: пиксель спрайта красится его цветом. Варианты записи: «OR в плоскости своего цвета, AND NOT
  при стирании только в них» (дёшево, наложение разных цветов смешивается и восстанавливается при стирании)
  или «последний рисующий — его цвет» (дороже). Выбрать по замеру.

## i8080: устройство (src/vec)
- Переменные игры — по адресам ZX (0x5CCB..0x5DFF, FRAMES 0x5C78), буферы спрайтов 0x5E00.. (свой формат),
  код 0x0100.., данные 0x6000.. (tools/mkvecdata.py из картриджной сборки), стек вниз от 0x5B00.
- Текущий объект — копия ws (8 байт) + cur; диспетчер копирует туда и обратно; подпрограммы, которые
  переписывают объекты (новый уровень, конец хода), делают ws_flush. Пустой слот не копируется.
- Вывод (render.asm): плоскости 0x80/0xA0/0xC0 — INK (белый, красный, зелёный — по одной плоскости),
  0xE0 — «чёрная» (предметы цвета 0, палитра не показывает; стирается, только если что-то рисовали).
  Стирание кадра — AND NOT только в плоскостях прошлого цвета объекта (lastcol; ракета и взрывы — во всех),
  рисование откладывается до ColourizeSprite (цвет объекта) — без клэша. Пиксели другого цвета под кадром не
  прорезаются (на ZX прорезались): объединение плоскостей местами шире экрана ZX («лишние точки» в lock80),
  логика из-за этого расходится редко (s1_bot: 1 проход из 15000 — лазер остановился иначе). Решение
  владельца 26.10 ради скорости. Блиттер: SP = данные спрайта (по столбцам, снизу вверх), развёрнутые пары pop, вход по таблице.
  Неподвижный кадр того же цвета не стирается, а дорисовывается OR (объединение то же: U&~S|S = U|S).
- Ракета: модули рисуются полосами по 8 строк своими цветами (заправка, мигание) — как атрибуты ZX.
- Темп: FrameRateLimiter (пустой слот без смены кадра) — пауза 120 витков (на ZX 192 витка ≈ 5000 тактов;
  уменьшено, т.к. работа прохода у i8080 тяжелее). Звук с 26.10 — асинхронно на ВИ53 (канал 2, из прерывания),
  игра его не ждёт (на ZX ждала): +7 % к скорости прохода. Итог по
  эталонам: проход Вектора 0,86..1,13 от ZX («темп» в выводе lock80; ISR Вектора не учтён).
- Прерывание не считает кадры во время вложенного прохода (frame_ticked) — как ZX с DI.
- ld a,r на Векторе — генератор get_r_vec; на сверке — очередь эталона.

## Открытое
- Скорость (26.10, после стирания своих плоскостей): тяжёлые сценарии ~ как ZX (s1_bot 2,21 / 2,15 кадра,
  s6 2,12 / 2,09), лёгкие на 10–17 % быстрее. Пробовал и откатил: пропуск перерисовки неподвижных объектов по
  «штампам» столбцов (дороже выигрыша, ломал новый предмет в слоте); pre-inverted данные — не стоят памяти.
- Пауза SHIFT не назначена на клавишу Вектора.
- Звук (26.10): эффект = шаги «делитель ВИ53 + длительность» по тактам петель бипера ZX с поправкой ~1,2 на спорную
  память; канал 0 ВИ53 — секундомер (режим 2, 0xFFFF), шаги переключает snd_poll из диспетчера объектов (точнее
  кадра) и прерывание; лазер — 6 шагов вниз (~14 мс), взрыв — 4 шага вверх, меандры — C периодов. Канал 2 — тон.
  Мелодия старта (docs/BBC_TUNE.md) — каналы 0..2, после неё timer_init. Проверить на слух.
- Музыки в оригинале нет — только эффекты бипера.
- Проверка на MiSTer и в Emu80 — не делалась.
- Заставка (loading_screen 6912 Б) не используется.

## Режимы и мелочи (26.10)
- Бессмертие: в меню F1+F3 (ряд 1 матрицы, биты 0x08|0x20) — старт с god_mode = 1: пришелец при касании
  взрывается, Джетмен живёт (alien_coll_anim_sfx не зовёт explosion_after_kill). Обычный старт сбрасывает.
- Пауза — ВК (вкл/выкл), в меню сбрасывается.
- game_over сбрасывается на старте игры (иначе вторая игра после конца сразу уходила в меню).
