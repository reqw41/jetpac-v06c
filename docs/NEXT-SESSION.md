# Jetpac → Вектор-06Ц: старт следующей сессии

Создано 25.10.2026. Сделано: папка, git, подмодуль `upstream/`
(mrcook/jetpac-disassembly, 69dcde1), SkoolKit в `.venv`, `tools/sjasmplus` (из alien8-v06c),
эталон ZX без окна (`tools/mkbin.sh`, `tools/zxshot.sh`). **Решено: цвет — 3 плоскости, без клэша.**

## Что за исходник

- `upstream/jetpac.skool` — полный дизассемблер картриджной версии (SkoolKit), всё размечено:
  265 меток, 3732 инструкции. Собирать только через `tools/mkbin.sh` → `build/jetpac.bin`
  (0x5CCB–0x9C92, 16328 Б) и `build/jetpac_z80.asm`. Две ловушки голого skool2bin:
  * блоки `i$` («Old unused routines» 0x6EFA, 0x72CB, 0x7F9D) он выбрасывает и сдвигает всё после
    них — mkbin.sh подменяет их на `defs` нужной длины (проверка: 0 сдвигов, 0 расхождений defb);
  * без `-s` остаётся оригинальный `ld de,$3a00` (шрифт в ПЗУ картриджа на 0x3B00) и на ZX с
    обычным ПЗУ текст выходит сплошными полосами. С `-s` берётся копия шрифта `system_font`.
- **Эталон = картриджная сборка из skool** (`tools/zxshot.sh menu|game`: SkoolKit `trace.py`
  с ПЗУ 48K, PNG экрана). Меню совпадает с кассетой (кроме «JOYSTICK» вместо «KEMPSTON JOYSTICK»),
  игра идёт: уровень 1, без ввода Джетмен гибнет и игра возвращается в меню.
- Оригиналы от пользователя — `orig/` (в .gitignore): кассета `[a][16K].tzx` (md5 a8728878…) и
  снимок `.sp` (md5 2a2b57b5…, 48K). В области 0x6000–0x7FFF они побайтно равны друг другу,
  но это **другая сборка**, не картридж: код сдвинут кусками (+75, +55 … байт), в начале вставлена
  строка COPYRIGHT. Побайтно с дизассемблером не сравнить — только визуально/по поведению.
  `tools/cmp_orig.py` — сверка образа с `build/jetpac.bin`; `build/jetpac_tape.z80` делается
  `tap2sna.py` из .tzx.

## Карта памяти ZX

    0x4000-0x57FF  экран ZX, 0x5800-0x5AFF атрибуты (игра рисует прямо в экран, XOR, без теневого буфера)
    0x5CCB-0x5FFF  стек (37 Б, ld sp,stack_memory+$25) и переменные
    0x6000-0x7FB2  код и данные игры (~8 КБ); 0x6000 jp 0x61BF (EntryPoint)
    0x7FB3-0x9AB2  loading_screen (6912 Б, экран ZX целиком — для заставки)
    0x9AB3-0x9C66  system_font (кусок шрифта ZX ROM; код берёт system_font-0x100)

Сама игра ~9 КБ — на ванильном Векторе (экран 0x8000–0xFFFF) помещается в 0x0100–0x7FFF
с большим запасом. Заставку и шрифт переложить ниже 0x8000 (ссылки на них — по меткам).

## Точки соприкосновения с железом ZX (по `build/jetpac_z80.asm`)

- Экран: `Coord2Scr` (стр. ~4205), `ScreenPosOnePixelAbove`, `ClearScreen`, `DrawFontChar`,
  `DrawPlatformTile`, `MaskSprite`, буферные `BufferCopy*`/`BufferFlipSprite`.
- Цвет: `ColourizeSprite`, `Coord2AttrFile`, `ClearAttrFile`, `UpdateRocketColour`, прямой `$5820`.
- Время: `SYSVAR_FRAMES` (0x5C78, тикает ПЗУ ZX по IM1), `FrameRateLimiter`, `ei` в стр. ~2189.
- Ввод: `in a,($fe)` ×8, `out ($fd),a` ×7 (картриджная особенность, на Векторе выбросить),
  `ReadInterface2Joystick` → джойстик «П» как в прошлых портах.
- Звук: бипер `out ($fe)` (`PlaySquareWave*`, `SfxPlayExplosion`) → порт 0 / ВИ53.
- `jp (hl)` в MainLoop (диспетчер актёров), `ld sp` ×2.

## Z80-специфика (сколько переводить)

ix 305 (iy нет), jr 240, bit/set/res 173, djnz 38, exx 33, ex af 18, neg 15, rl/rr/sla/srl 19,
adc/sbc hl 8, ldir 6. Переводчик Z80→i8080 есть: `~/projects/alien8-v06c/tools/a8_z80_to_8080.py`
(+ `check_i8080.py`, `check_djnz.py`, `check_ixflags.py`) — начать с его адаптации.

## Предлагаемый план

1. ~~Оракул~~ — готов (картриджная сборка + trace.py). Для локстепа понадобится трасса по кадрам:
   trace.py умеет `--map`, `-S`, или MAME как в `knightlore-research/zx-stand`.
2. **Перевод Z80→i8080** всего кода; ix-структуры актёров — на HL/DE или фиксированные адреса.
3. **Экран.** Вывод в плоскость Вектора вместо раскладки ZX: `Coord2Scr` → столбцовая адресация
   Вектора (адрес = 0x8000+плоскость + x/8·256 + (255−y)), XOR-спрайты сохраняются.
4. **Цвет — решено: 3 плоскости, без клэша.** Плоскости 0–2 = биты INK ZX (палитра — 8 ярких
   цветов ZX, BRIGHT в игре стоит почти везде: атрибуты 0x4x). Цвет объекта уже есть в его
   записи — `(ix+$03)`, его же берёт `ColourizeSprite`. Значит:
   * рисовальщики (`MaskSprite`, `DrawFontChar`/`DrawCharPixels`, `DrawPlatformTile`, лазер)
     XOR-ят байт в те плоскости, где бит INK = 1 (в остальные — ничего);
   * `ColourizeSprite`, `Coord2AttrFile`-запись, `ClearAttrFile` — в пустышки (атрибутов нет);
   * стирание тоже XOR, поэтому стирать надо **тем же цветом, каким рисовали**. Где цвет меняется
     у нарисованного объекта (`UpdateRocketColour` — заливка ракеты топливом, `ItemDropRandomColour`,
     смена цвета лазера, мигание надписей) — стереть старым цветом, нарисовать новым, либо
     хранить «цвет на экране» в записи объекта;
   * пересечение объектов разного цвета даст смесь плоскостей (XOR) — это попиксельно, клэша нет;
   * FLASH в меню (`menu_colour_table`, бит 7) — перерисовкой или сменой палитры по кадрам.
   4-я плоскость свободна (фон/звёзды или ускорение стирания — потом). Цена — до трёх XOR на
   байт спрайта; замерить на кадр, бюджет ZX — 50 Гц с `FrameRateLimiter`.
5. **Время, ввод, звук**: прерывание Вектора 50 Гц тикает свой FRAMES; клавиатура + джойстик «П»;
   бипер → порт 0 (или ВИ53).
6. **Сверка**: локстеп логики против ZX (рецепт `~/projects/knightlore-v06c/docs/PORT_RECIPE.md`),
   гейты headless на V06JS (`~/projects/vector06js`), образы `rom/*.rom` (+ .c00 для MiSTer).
